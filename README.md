# Soulgame CMS · 运营后台原型

可点击的后台原型（纯 HTML + CSS + JS，不用构建），用浏览器直接打开 `index.html`。

在线体验：https://suda-go.github.io/soulgame-cms-prototype/

- 依据：[Soulgame V7 CMS 运营后台规划](https://mi.feishu.cn/docx/KvhcdugPro47OLxL1OQc0OTtn3d)
- app 原型：https://suda-go.github.io/play-zone-prototype-v7/

## 怎么用

- 右上角切换**演示角色**（运营、客服、审核、财务、研发、产品、管理员），看不同的人能做什么、要谁审批
- 改过的数据存在这台电脑的浏览器里（localStorage `sg.cms.v1`），刷新还在；右上角“重置演示数据”恢复初始值
- 演示数据按固定种子生成：33 个用户、约 2,000 条账本、850 局对局，以及举报、签名复审、订单、退款、匹配单、对账、待审批等场景

## 做了什么

P0 全部可操作，P1 里的“数值总览”也做了；其他 P1 页面是占位，写了要做什么和为什么放 P1。

| 菜单 | 页面 |
|-|-|
| 用户管理 | 用户查询（展示 ID、user_id、邮箱、三方 ID、设备 ID、昵称）；用户详情 13 个标签；封号 / 解封、强制下线、清空签名、重置昵称头像、金币调整、发放装扮；注销记录 |
| 内容安全与风控 | 举报处理（按被举报人合并，附局内表情快捷语记录、对局数据、私聊片段）；签名复审；敏感词库（带检测）；处罚记录 |
| 玩法配置 | 游戏、场次、匹配参数、机器人（两种方案都能配）、对局参数、表情和快捷语、好友房 |
| 福利与任务 | 新手礼包、离线收益、奖池翻倍、7 日签到、任务（专用编辑器）、神秘任务、宝箱奖池、防刷参数、数值总览 |
| 商城与会员 | 装扮（专用编辑器，头像框实时预览）、充值档位、会员档位与权益（三档并排 + 对比表预览）、通话计费 |
| 订单与资金 | 订单和订阅、补单和退款、金币账本（可导出）、匹配单与托管（可作废退还）、对账告警 |
| 消息与触达 | 系统消息模板、推送模板、分享 |
| 系统配置 | 协议与客服、默认资料、展示数字、资料与社交限制、多语言文案（含配置缺翻译检查）、跳转目标 |
| 后台基础 | 审批中心、配置发布记录、操作日志、账号与角色 |

配置都走同一套流程：改了自动存草稿 → 提交发布（校验、差异、发布后的影响、每天理论上限）→ 普通配置直接生效，动到金币的要产品审批，机器人参数要产品 + 研发负责人两级审批 → 版本记录里可以回滚。

## 可以先试

1. 运营：在“7日签到”把第 7 天改成 800 → 提交发布，看每天理论上限的变化
2. 产品：在“审批中心”审“限时任务：分享5次”
3. 审核：处理举报里的维克多（挂机）、LoserTrash99（辱骂）
4. 客服：查用户“阿凯”付了钱没到账，发起补单；财务：在“补单和退款”处理，再看马可的退款扣回（金币不够扣）
5. 在“装扮”新建一个头像框，拖滑块看戴在头像上的效果

## 文件

```
index.html
css/cms.css
js/data.js            语言、角色和权限、计数项、账本类型等静态定义
js/seed-config.js     配置的首发值（来自各需求文档和 app 原型）
js/seed-data.js       演示用户、账本、对局
js/seed-scenarios.js  举报、复审、订单、退款、匹配单、对账、待审批等场景
js/store.js           状态、配置版本和审批、各种操作、数值总览算法
js/schemas.js         每类配置的字段、权限、审批级别、校验、差异
js/ui.js  js/app.js   组件、路由和菜单
js/emoji.js           局内表情（从 app 原型拷来的同一套画法）
js/pages/             各页面；form.js 按 schema 生成表单，editors-*.js 是任务、装扮、会员、多语言的专用编辑器
```

素材（头像、头像框、背景）从 app 原型 `app-demo-v7/assets` 拷来。
